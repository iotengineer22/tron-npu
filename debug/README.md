# EK-RA8P1 書き込み用バイナリフォルダ (debug)

本フォルダは、μT-Kernel 3.0 および各種エッジAIプログラムを Renesas EK-RA8P1 評価ボードへ書き込むためのバイナリファイル（`.srec` および `.elf`）を集約・整理したフォルダです。

---

## 1. フォルダ構成

本フォルダは、作業効率化のために以下のように役割別に整理されています。

* **`debug/` 直下 (メイン)**:
  実機での動作デモや審査で使用する、**Arm Ethos-U55 NPUによる高速AI処理**が有効になった代表的な3つのプログラムです。
  * `tron_yolo_face_npu.srec` (YOLO顔検出 NPU高速版)
  * `tron_img_npu.srec` (MobileNet画像分類 NPU高速版)
  * `tron_edge_fomo_npu_type.srec` (FOMO基板部品検出 NPU高速版)
* **`base_firmware/`**:
  液晶描画やカメラ接続テストなど、基本ペリフェラルとRTOSの動作検証用プログラムのSRECです。
* **`cpu_ai_versions/`**:
  NPU高速化の効果を比較するために開発された、**CPU通常処理版**のAIプログラムのSRECです（推論速度の違いを測定するために使用します）。
* **`elf_files/`**:
  e2 studioのデバッガ等からロードしてステップ実行などを行う場合に使用する、シンボル情報付きのデバッグ用ELFファイル群です。

---

## 2. 書き込み手順 (Renesas Flash Programmer 使用)

書き込みソフト **Renesas Flash Programmer (RFP)** を使用してボードにプログラムを書き込む標準手順です。

### ① ハードウェアの接続
1. パソコンと EK-RA8P1 ボード上のオンボードデバッガ用USBポート **`DEBUG1`**（micro-USB または USB-C）をUSBケーブルで接続します。
2. ボードの電源が入っている（LEDが点灯している）ことを確認します。

### ② RFP プロジェクトの作成（初回のみ）
1. **Renesas Flash Programmer (RFP)** を起動します。
2. **[ファイル] ➡ [新しいプロジェクトの作成...]** を選択し、以下のように設定します。
   * **マイクロコントローラ**: `RA` （自動認識で詳細型番が `R7KA8P1KFLCAC` になります）
   * **プロジェクト名**: 任意の名前（例: `RA8P1_Write`）
   * **作成場所**: 任意の場所
   * **通信ツール**: `J-Link`
3. **[接続]** ボタンをクリックして、ボードと正常に通信できることを確認します。

### ③ プログラムの書き込み
1. 画面中央の「プログラムファイルとユーザー鍵」の入力欄の右側にある **[参照...]** ボタンをクリックします。
2. 本 `debug/` フォルダ配下から、書き込みたいプログラムの **`.srec` ファイル**（例: `tron_yolo_face_npu.srec`）を選択します。
3. 画面下部の大きな **[スタート(S)]** ボタンをクリックします。
4. フラッシュメモリの消去とプログラムの書き込みが走り、右側に緑色の背景で **「操作が成功しました」** と表示されれば完了です。
5. ボード上の `RESET` ボタン（赤色スイッチ付近の黒いリセットボタン）を押すか、USBケーブルを挿し直すと、書き込まれたプログラムが起動します。

## 3. トラブルシューティング：アドレスエラー (E1000008) の解決法

### 発生する現象
容量の大きいAIプログラムを書き込む際、RFPのログ画面に以下のようなエラーが表示されて書き込みが失敗することがあります。
> `エラー(E1000008): デバイスでアドレスエラーが発生しました。(Command: 13, Response: D2)`

### 原因
RAマイコンのセキュリティ機能（TrustZone）による**セキュア/ノンセキュアのメモリ仕切り（境界設定）**が原因です。
以前に書き込んだプログラムの古いサイズ境界設定がマイコン側に残っている状態で、それより容量の大きいAIプログラム（YOLOやMobileNetなど）を上書きしようとすると、安全装置が働いて書き込みが強制的にブロックされます。

### 解決手順 (デバイスの初期化)
RFP上からマイコンのセキュリティ境界設定を一度工場出荷状態（フラット）にリセットすることで、即座に解消できます。
1. RFPの画面上部メニューバーにある **`ターゲットデバイス(D)`** をクリックします。
2. ドロップダウンメニューから **`デバイスの初期化(I)...`** を選択して実行します。
3. 画面右側に「デバイスの初期化が成功しました」と表示されるのを待ちます。
4. 元の画面に戻り、再度 **[スタート]** をクリックして書き込みを実行します。
   * （仕切りがリセットされたため、今度はエラーなく100%正常に書き込めます）

## 4. バイナリファイルの更新方法

開発環境（e2 studio）でソースコードを変更して再ビルドした後は、本リポジトリの**ルートディレクトリ**にある **`collect_binaries.bat`** をダブルクリックして実行するだけで、各プロジェクトから最新の `.elf` と `.srec` を自動で本 `debug/` フォルダへ再集約・クリーンアップ（RFPエラー対策のOFSフィルタ処理含む）することができます。
